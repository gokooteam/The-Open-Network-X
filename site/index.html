Open Network Xon-x.live·README.md

The goal is not to reproduce an existing implementation.

Most networks that share an architecture begin as a fork: take working source code, change it, deploy it. ONX begins one step earlier, with the published design. Each requirement is restated as an ONX specification, every ambiguity or gap gets a recorded decision, and only then is code written, followed by tests that try to prove it wrong.

Open Network Xon-x.live·Oct 8

Blocks are signed, devnet-1 has its first block, and v0.2.0 is tagged.

Until now nothing proved who produced a block. Block files are now ONXBLK05: the header grew to 160 bytes with a protocol_version and a producer-stamped block_time, and every block carries a signature section. onxd signs each block with a key that must belong to a genesis validator, and onx replay refuses a block unless enough genesis stake signed it and its block_time did not go backwards. The state transition itself still never reads a clock.

  • devnet-1: one producer run by the project, with a faucet account in genesis. Its blocks are published for the explorer.
  • on-x-scan.com checks every block against the pinned genesis hash in your browser. It decodes signatures but does not verify them yet.
  • The currency is now called Onyxi, ticker ONXI (ADR-0033). No consensus bytes changed.
  • One version for the whole workspace, a changelog, and release automation. v0.2.0 is the first tag.

devnet-1 is not a public testnet: one producer, no peers, no consensus. A testnet other people can join is milestone M7.

Open Network Xon-x.live·Oct 5

The chain now runs on messages.

Synchronous transfers are gone. Following the actor model in the specification, accounts only interact through messages: a signed external message enters a block, a built-in wallet handler authenticates it, and the value travels on as an internal message that the receiver processes as its own transaction.

  • Signatures bind the chain ID, so a message signed for one chain fails on another
  • Addresses derive from keys (ONX_ADDR_V1): a new account can receive, then spend by revealing its key
  • Failed deliveries bounce the value back, minus fees
  • Delivery order is FIFO per sender and receiver, and an internal message is never delivered twice

Single shard for now: delivery happens within the block. Cross-shard routing is still specified only. Seven new decision records cover the design.

One transfer, end to endsingle shard

  1. External messageSigned off-chain, submitted to a block. The signature covers the chain ID.ONX_MSG_EXT_SIGN_V1
  2. Wallet handlerBuilt into the state transition: checks chain ID, key, nonce and signature, takes the fee, bumps the nonce.apply_messages, phase 1
  3. Internal messageDerived, never submitted. Queued in order, one per external message.ONX_MSG_INT_V1
  4. DeliveryRuns as the receiver's own transaction, FIFO per sender and receiver, in the same block. Contracts execute on the TVM here.apply_messages, phase 2
  5. BounceIf delivery fails, the value goes back to the sender minus fees already taken. The block stays valid.ADR-0004

Open Network Xon-x.live·Oct 5

TVM on the spine: contracts execute, and the node produces blocks.

Contract calls now run on the TVM inside the state transition. A test counter contract goes from 0 to 3 through the real onx replay binary in two separate processes, with byte-identical roots. A contract that throws has its delivery bounced instead of breaking the block.

onxd now runs a real single-node loop: messages dropped into a spool directory are checked at the door, then drained into blocks on demand, with no empty blocks and no wall-clock in block content. Its output replays through onx replay to identical roots. Networking stays off.

Also: 8 golden vectors derived by hand in Python straight from the spec documents, including an Ed25519 signature made with libsodium. All matched the Rust implementation.

Not yet: messages sent out by contracts, multi-cell code, gas refunds.

Since changed: headers now carry a block_time stamped by the producer (pull request #14). The state transition still never reads a clock; replay only checks that block times never go backwards.

CI green-up: crash-atomic database init, rustls audit fix.

The red CI run was hiding a real bug. On slow runners, a kill -9 could land while the chain database was first being created, leaving a half-written file that refused to reopen. Open Network Xon-x.live·Oct 5

Transactions are now signed (ONX_TX_V2).

Every transfer carries an Ed25519 signature and the sender's next nonce, so a signed transfer can be applied exactly once. Accounts with no key can receive but never spend.

Same change: storage refuses blocks that don't chain off the stored head, and every resume checks the rebuilt state root against the stored one. Golden vectors were refrozen on the new format.

Since superseded: signing moved to external messages, and keyless addresses can now spend by revealing their key. See the message-model post above.

Open Network Xon-x.live·Oct 5

Deterministic replay milestone: phases 0–5 complete.

Same input. Same state. Same result.

onx replay loads a genesis document and applies each block through a pure state-transition function (no clocks, no randomness, no I/O), then persists the result in one atomic write. Run it twice, or kill it halfway and resume, and it has to land on the same state root.

  • Canonical encodings, byte-identical across processes
  • A real binary genesis whose hash is the chain ID
  • A pure state transition with fees
  • Atomic storage on redb with crash recovery
  • The onx replay command and its acceptance suite

sharding.mdADR-0019

Every balance lives in an account, and every account is in exactly one state: Uninitialized, Active, Frozen or Destroyed. Contract accounts also carry code and data cells.

In ONX today: implemented and tested. An address is derived from its owner's public key, so a new account can receive first and spend later by revealing the key. Spending means signing an external message bound to this chain, with the account's next nonce.

Onyxi

Native protocol currency.

The currency is part of the protocol. It is not the reason the protocol exists.

Onyxi (ticker ONXI) is defined inside the ONX protocol rather than as an application-layer token. It pays fees and storage and secures validator stake. Parameters below are recorded in ADR-0026 (accepted 2026-09-10) and onx-economics; the name comes from ADR-0033.

Denomination
1 Onyxi = 109 nano-Onyxi
TESTED
Every balance and amount in the state transition.
Transaction fees
50% burned, 50% to validators
TESTED
The state transition burns half and credits half to the fee collector named in the block header.
Initial supply
5,000,000,000 Onyxi
SPECIFIED
A constant in onx-economics; no network issues it.
Validator rewards
1.75% a year on active stake
SPECIFIED
Not exercised; there are no running validators.
Storage fees
10 nano-Onyxi / byte / 106 lt
SPECIFIED
Not yet charged by the state transition.

No public network exists, so Onyxi exists only inside test chains such as devnet-1. This post lists protocol parameters and makes no statement about value.
