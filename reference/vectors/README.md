# Reference vectors

Checked-in fixtures generated by `python3 reference/gen_vectors.py` from
the Python reference implementation. Regenerating must produce
byte-identical files; CI runs `gen_vectors.py --check` and fails on drift.

## Files

**`genesis.json`** — the fixed test genesis:
- `chain_id`: 32-byte hex (the fixture's genesis hash; bound into every
  message signature per ADR-0005)
- `workchain`: -1 (masterchain)
- `genesis_root`: expected initial state root (hex)
- `accounts`: sorted by ID; each has `id`, `balance_nanos` (decimal
  string), `pubkey` (hex), `nonce`, `lt`

**`blocks.json`** — the 5 blocks:
- Per block: `seqno`, `prev_hash`, `lt`, `workchain`, `fee_collector`,
  `msgs_root`, `state_root`, `msg_count`, `block_hash`, `header_hex`
  (148-byte header), `messages` (external message wire encodings, hex),
  `block_file_hex` (complete `ONXBLK04` block file — feedable directly to
  the Rust `onx replay` binary)

**`expectations.json`** — what execution must produce:
- Per block: `seqno`, `state_root`, and `receipts` — one per external
  message, each with `msg_hash`, `fee_burned`, `fee_validator`, and
  `deliveries` (each with `msg_id`, `value`, `bounced`, `gas_used`)

## Intended consumers

- **Rust tests** (future): parse `blocks.json` with the Rust decoders,
  apply via the STF, and assert the roots and receipts in
  `expectations.json`. No Python needed at Rust test time.
- **Humans**: the JSON is the human-readable proof that the two
  implementations agree.

## Regenerating

```sh
python3 reference/gen_vectors.py          # rewrite the three files
python3 reference/gen_vectors.py --check # fail if they would change
```
